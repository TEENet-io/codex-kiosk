# 版本适配与维护指南

本文记录 Codex 桌面版更新后，如何把本仓库的补丁适配到新版本。

补丁不是调用官方 API，而是对**压缩混淆后的 JavaScript** 做模式匹配和原地改写。
因此 OpenAI 每发布一个新版本，都可能让部分补丁失配，构建随之失败。
这是本方案的固有成本，不是缺陷——换来的是**正品 Codex、功能不阉割**。

---

## 一、先理解一件事：“最新版”不是确定的

`config/codex-only-local.json` 里 `appSource.mode` 为 `rg_adguard`，
即每次构建都取 Microsoft Store 上的**当前最新版**。

但在 OpenAI 灰度发布期间，**同一个查询会随机返回不同版本**。
2026-08-14 实测，同一台机器、同一分钟内连续三次查询：

```
第1次: 26.810.4967.0
第2次: 26.803.10989.0
第3次: 26.803.10989.0
```

这不是 rg-adguard 的问题——直连微软官方 Windows Update 端点（fe3.delivery.mp.microsoft.com）
结果一样。灰度期间后端节点各自持有不同的“最新版”。

### 由此产生的现象

- **同一个 commit，重跑 CI 可能一次绿一次红**；
- 本地拿到的版本可能和 CI 拿到的不同，导致“本地复现不了 CI 的失败”。

### 应对策略

**让补丁同时兼容灰度期间在发的所有版本。**
现有正则保持不动，针对新版**追加**一个 fallback 变体。
这样无论构建时掷到哪个版本都能通过，且老版本行为零风险。

> 判断 CI 到底构建了哪个版本：看 **Resolve source version** 步骤输出的 `version`，
> 或对比日志里的 bundle 文件名（如 `main-BaCWCruR.js`）——文件名带内容哈希，版本不同必然不同。

---

## 二、本地复现（关键能力）

**不要拿 CI 当调试器。** CI 一轮几十分钟且只报第一个错误。
本地可在几分钟内跑完整个补丁流程，并一次看到全部失配点。

### 1. 获取 MSIX

```bash
# 取当前最新版的下载直链（纯 HTTP，不需要 Playwright）
curl -s -X POST 'https://store.rg-adguard.net/api/GetFiles' \
  -H 'content-type: application/x-www-form-urlencoded' \
  -H 'referer: https://store.rg-adguard.net/' \
  -H 'user-agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/145 Safari/537.36' \
  --data-urlencode 'type=PackageFamilyName' \
  --data-urlencode 'url=OpenAI.Codex_2p2nqsd0c76g0' \
  --data-urlencode 'ring=Retail' --data-urlencode 'lang='
```

返回的 HTML 表格里含微软 CDN 直链（`tlu.dl.delivery.mp.microsoft.com`）和 SHA-1。
下载后**务必核对 SHA-1**。

> 直链约 4 小时过期；`http://` 是 Windows Update 的正规形态，完整性由 SHA-1 + MSIX 签名保证。
> rg-adguard 只是代取直链，包本身是微软官方原件。
>
> **注意：该接口只返回当前最新版，无法点名要历史版本。**
> 想长期保留某个版本，只能自己把 MSIX 存档。

### 2. 解包并运行补丁

MSIX 本质是 ZIP：

```bash
# 解出 app 目录（补丁脚本的输入）
unzip -o -q OpenAI.Codex_<版本>_x64.msix 'app/*' -d stage

# 运行真实的补丁脚本，与 CI 完全相同的调用方式
node scripts/patch-app-asar.mjs --app-dir ./stage/app; echo "EXIT=$?"
```

**每次重跑前必须重新解压 `stage`**——补丁会就地修改文件，第二次运行结果不可信。

`EXIT=0` 且输出 `all patches applied or already correct.` 才算通过。

### 3. 回归测试

适配新版本后，**必须同时验证旧版本仍然通过**，否则灰度期间掷到旧版就会红。

## 三、适配一个失配的补丁

1. **定位补丁在找什么**：在 `scripts/patch-app-asar.mjs` 中找到对应的正则。
2. **找到旧版命中的代码**：在能通过的那个版本的 bundle 里搜锚点字符串。
3. **找到新版的同一段**：在新版 bundle 里搜同样的稳定字面量
   （字符串常量、gate id、URL 路径等——这些比变量名稳定得多）。
4. **逐字符对比**，找出真正变化的部分。
5. **追加一个放宽后的变体**作为 fallback，不要修改原正则。

### 渲染层主文件位置

```
webview/assets/app-initial-<hash>.js      # 主渲染层
webview/assets/data-controls-<hash>.js    # 设置 / 数据控制面板
.vite/build/main-<hash>.js                # 主进程
```

### 放宽正则的两条铁律

**1. 必须验证匹配唯一。**

```js
const matches = [...content.matchAll(new RegExp(RE.source, 'g'))];
// 必须恰好为 1
```

放宽后若匹配到错误位置，会产出一个**“补丁号称成功、ChatGPT 其实还在”**的安装包——
这是本项目最严重的失败模式，比构建失败危险得多。

**2. 绝不把必需补丁降级成警告。**

`assertRequiredPatchesApplied()` 和 `failRequiredPatch()` 存在的意义就是让漂移
**红给你看**。宁可构建失败，也不能静默发出可能泄露 ChatGPT 入口的包。

### 变量改名 vs 结构变化

补丁用捕获组抓变量名，因此**混淆器改名（`S`→`E`）不会导致失配**。
真正打垮补丁的是**结构变化**：新插入的语句、多出来的条件分支。

## 四、已适配版本

| 版本 | 发布 | x64 SHA-1 | 大小 |
|---|---|---|---|
| 26.803.10989.0 | 2026-08-03 | `d4626f337aeb4e34a12f0e3c9fa1a559ab1377c3` | 640.5 MB |
| 26.810.4967.0 | 2026-08-13 | `5059b4f94c739afa237bfc4a9ef1df70dc1a1e5d` | 711.4 MB |

> 版本号是**日期格式**，不是语义化版本：`26.810` = 2026-08-10。
> `803 → 810` 是整整一周的开发量，不是小补丁：
> 整包 +71 MB，webview 资源从 4,710 个增至 7,576 个。

### 26.810 相对 26.803 的实际变化

| 补丁 | 变化 |
|---|---|
| node_repl 工具列表 | `deferLoading` 判断新增第二个分支 |
| node_repl 调用桥接 | 插入线程归属 / 实时委派 / 多端协调三段新逻辑；plugin 分支扩至 `openai_settings` |
| 归档设置可见性 | isError 重构为 `<items>.length===0&&(本地‖云任务‖ChatGPT会话)` |
| 7 个核心 codex-only 补丁 | 仅混淆器改名 |
| codex-only-startup | 独立函数被内联进 Jotai getter（唯一的真重构） |

## 五、常见故障

### `Pinned version X not found among rg-adguard candidates`

该接口只发最新版，无法锁定历史版本。要固定版本必须自行存档 MSIX。

### `browserType.launch: Executable doesn't exist`

Playwright 浏览器未安装。**安装步骤必须排在 Resolve source version 之前**——
resolver 每次都会执行，且可能回退到浏览器流程。

### `Could not apply required Codex-only/local-tasks patch`

核心补丁失配，按第三节适配。**不要跳过。**

### `Portable zip is missing required file: ...`

上游改了文件布局。先确认该文件在新版 MSIX 里是否真的存在（可能只是换了路径），
再决定是修构建逻辑还是调整清单。

### `The variable '$xxx' cannot be retrieved because it has not been set`

`crossPlatformWeb: false` 的连带影响：变量在 web-gateway 门控块内赋值、块外使用。
StrictMode 下即报错。

## 六、必须人工验收的部分

自动化只能验证到**“补丁已正确应用”**这一层。
以下只能在 Windows 真机上确认，**每次发布前必做**：

1. ChatGPT 入口确实消失（侧边栏、设置、新建会话处逐一检查）；
2. Computer Use 正常可用；
3. 云任务列表与详情确实禁用；
4. Codex 本地任务、终端、文件编辑、MCP、技能未被误伤；
5. 安装、登录、重启、卸载全流程正常。

CI 即使全绿，也**不代表**上述任何一条成立。
